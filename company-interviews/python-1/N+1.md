Great question, Ashish — the N+1 connections problem in FastAPI (or any web app) usually refers to the situation where your code opens a new database connection for every query inside a loop or request, instead of reusing a single connection or batching queries. This leads to performance bottlenecks and wasted resources.
---
🔎 What causes N+1?
Imagine you fetch a list of users, then for each user you query their orders:
# BAD: N+1 queries
users = db.query(User).all()
for user in users:
    orders = db.query(Order).filter(Order.user_id == user.id).all()

First query → get all users (1 query).
Then one query per user → N queries.
Total = N+1 queries (inefficient).
---
✅ How to handle N+1 in FastAPI
Use eager loading / joins
With SQLAlchemy, you can fetch related data in one query:
from sqlalchemy.orm import joinedload

users = db.query(User).options(joinedload(User.orders)).all()

This loads users and their orders in a single query.
Connection pooling
Use a sessionmaker with a connection pool (e.g., via SQLAlchemy’s create_engine(pool_size=...)).
In FastAPI, manage sessions with a dependency:
from sqlalchemy.orm import Session

def get_db():
    db = SessionLocal()
    try:
        yield db
    finally:
        db.close()

Then inject into endpoints:
@app.get("/users")
def get_users(db: Session = Depends(get_db)):
    return db.query(User).options(joinedload(User.orders)).all()

Batch queries
Instead of querying inside a loop, fetch all needed data at once:
orders = db.query(Order).filter(Order.user_id.in_([u.id for u in users])).all()

Async DB drivers
If you’re using async FastAPI, use async drivers like asyncpg or databases library with pooling to avoid opening a new connection per request.
---
📌 Interview-ready takeaway
“The N+1 problem happens when each item triggers its own query, leading to N+1 database calls. In FastAPI, we handle it by using SQLAlchemy’s eager loading (joinedload or selectinload), batching queries, and managing connections with dependency-injected sessions and connection pooling. This way, we reduce redundant queries and keep performance optimal.”
